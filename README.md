# QuickSpark

QuickSpark 是一个面向 Windows 的轻量级快捷启动器，核心体验是“全局快捷键唤起、输入、立即执行”。它以原生 Win32 界面实现，支持应用搜索、中文拼音、Everything 文件搜索、窗口切换、网页搜索、AI 问答与翻译、计算与换算、自定义指令、收藏置顶、系统操作、设置中心和内置说明书。

QuickSpark 当前不包含插件系统、账号系统、云同步、搜索历史或问答历史，也不会自行维护文件索引。网页由默认浏览器打开，文件搜索复用 Everything 已有索引。只有在主动执行网页搜索或 AI 提问时，查询内容才会发送给所选搜索引擎或配置的 AI 接口。它的目标是保持单进程、原生、可预测，而不是成为完整的桌面自动化或聊天平台。

## 功能概览

- 搜索开始菜单、桌面快捷方式以及 Windows/UWP 应用。
- 支持中文全拼、拼音首字母、英文子串和紧密模糊匹配。
- 根据相关性、收藏状态和本地使用频率排序。
- 通过 Everything 原生 IPC 搜索文件，不遍历磁盘。
- 按窗口标题查找并切换当前桌面窗口。
- 使用默认浏览器进行百度、必应和 Google 搜索。
- 通过自定义 OpenAI 兼容接口进行单轮 AI 问答和快捷翻译；流式阶段轻量显示，完成后渲染 Markdown，并可独立折叠显示 DeepSeek V4 思考内容。
- 内置四则运算、单位换算、日期计算和进制转换。
- 通过简单文本文件定义打开网页、目录、文件或 URI 的快捷指令。
- 提供亮暗主题、全局热键、开机启动、结果数量和默认搜索引擎设置。
- 支持托盘控制、单实例运行、DPI 缩放和内置使用说明。

## 当前功能边界

- AI 是单轮问答：不会把上一轮内容自动加入下一次请求，也不保存聊天历史。
- 文件搜索只调用 Everything 1.4.1 的原生 IPC，不兼容 Everything 未运行时的磁盘遍历回退。
- Markdown 使用原生 RichEdit 做轻量排版，不支持浏览器级 CSS、HTML、脚本、公式或交互组件。
- 自定义指令是受用户信任的本地目标映射：不会把 `cmd` 当作入口或自行解释命令行，但如果目标本身是脚本或可执行文件，Windows Shell 仍可能运行它。
- 当前没有第三方插件 ABI；未来若增加扩展，优先采用独立进程与 IPC，避免把不受信任的 DLL 加载进主进程。

## 运行要求

- Windows。
- 仅使用应用搜索、计算器等功能时，不需要额外软件。
- 使用文件搜索时，需要 Everything 1.4.1 或更高版本正在运行；QuickSpark 通过 Unicode Query2 IPC 查询，不自行建立文件索引。
- 使用 AI 问答或翻译时，需要用户自行提供可访问的 OpenAI 兼容 Chat Completions 接口；云端接口通常还需要 API Key。
- 从源码构建时，需要 Rust 工具链；建议使用 Windows MSVC 工具链及对应 Windows SDK。
- 仓库通过 `rust-toolchain.toml` 固定 Rust 1.95.0，并在 GitHub Actions 的 Windows 环境中执行格式、Clippy、Debug/Release 测试和发布构建。

## 快速开始

从源码构建并运行：

```powershell
cargo build --release
.\target\release\quickspark.exe
```

发布版 EXE 位于 `target\release\quickspark.exe`。当前版本免安装，程序启动后常驻系统托盘，默认按 `Alt + Space` 显示或隐藏搜索窗口。如果首选快捷键被占用，QuickSpark 会自动尝试其他内置组合并保存可用选项；即使全部被占用，也会继续启动到托盘。

EXE 可以移动，但如果已经启用开机自启动，需要在移动后进入设置中心，将“开机自动启动”关闭再开启一次，以更新注册表中的程序路径。设置和使用数据保存在 `%APPDATA%\QuickSpark`，不会写入 EXE 所在目录。

应用图标源文件位于 `assets/quickspark-icon.png`，多尺寸 Windows 图标位于 `assets/quickspark.ico`，构建时会自动嵌入 EXE。

## 应用搜索

直接输入文字即可搜索以下位置：

- 当前用户和所有用户的开始菜单。
- 当前用户和公共桌面。
- Windows/UWP 系统应用。

开始菜单和桌面索引识别 `.lnk`、`.exe`、`.url` 和 `.appref-ms` 文件。应用索引在后台线程中构建，不阻塞窗口；同名入口会合并。

匹配顺序主要考虑精确匹配、名称前缀、单词前缀、连续子串、中文全拼、拼音首字母和紧密模糊匹配。启动次数和最近使用时间只会微调同一相关性层级内的顺序，不会让不相关的高频应用越过更准确的结果。

选中普通桌面程序后，可以使用：

- `Enter`：正常启动。
- `Ctrl + Enter`：以管理员身份启动。
- `Ctrl + Shift + E`：在资源管理器中定位快捷方式或程序。
- `Ctrl + C`：复制索引目标路径。
- `Tab`：查看所有可用动作或固定到顶部。

UWP 应用不提供“以管理员身份运行”和“打开所在位置”。

## 内置使用说明

按 `F1`，或输入以下任一形式：

```text
?                     查看全部说明
? 文件                筛选文件搜索说明
help 计算器           筛选计算器说明
帮助 快捷键           筛选快捷键说明
manual                查看全部说明
说明书                查看全部说明
```

带示例的说明项按 `Enter` 会把示例填入搜索框，方便继续试用；按 `Tab` 可以复制完整说明。说明内容完全内置，不会打开网页或增加后台任务。

## 设置中心

输入 `settings`、`setting`、`set` 或 `设置`，也可以从托盘菜单打开设置中心。继续输入关键词可以筛选设置，例如 `设置 主题`。

当前支持：

- 全局唤起快捷键：`Alt+Space`、`Ctrl+Space`、`Alt+Q`、`Ctrl+Alt+Space` 循环切换。
- 开机自动启动。
- 亮色或暗色主题。
- 最多保留 8、12 或 20 条结果；默认 20 条，窗口同时显示 8 条。
- 默认网页搜索引擎：百度、必应或 Google。
- 查看所有功能前缀。
- 打开自定义指令配置文件。
- 查看 Everything 是否正在运行。
- 进入 AI 接口、模型和 API Key 设置。

选中设置项并按 `Enter` 即可更改。切换全局快捷键时，QuickSpark 会依次尝试其余组合；若只有原组合可用则继续保留，若四组都不可用则继续以托盘模式运行并提示稍后重试。

## 自定义快捷指令

输入 `; edit` 或在设置中心选择“自定义指令”，打开：

```text
%APPDATA%\QuickSpark\commands.txt
```

每行格式为：

```text
别名 | 显示标题 | 目标
```

### 固定网页和目录

```text
ds | 打开 DeepSeek | https://chat.deepseek.com/
bili | 打开哔哩哔哩 | https://www.bilibili.com/
docs | 打开文档目录 | %USERPROFILE%\Documents
```

使用示例：

```text
;                     列出全部自定义指令
; ds                  使用默认浏览器打开 DeepSeek
; docs                打开文档目录
```

### 带参数的网页搜索

目标中可以使用 `{query}` 占位符：

```text
bdx | 百度搜索 | https://www.baidu.com/s?wd={query}
gh | GitHub 搜索 | https://github.com/search?q={query}
```

使用时：

```text
; bdx 北京天气
; gh quick launcher
```

HTTP/HTTPS 目标中的参数会自动进行 URL 编码；目录、文件和其他 URI 目标使用原始参数。目标支持 `%USERPROFILE%` 等环境变量。也可以显式添加 `url:` 或 `path:` 前缀，但普通网址和路径无需添加。

配置规则：

- 空行以及以 `#` 开头的行会被忽略。
- 别名最长 32 个字符，不能包含空白或分号。
- `edit` 是保留别名，用于打开配置文件。
- 修改保存后无需重启；配置仅在使用自定义指令时读取。

## 收藏与置顶

选中应用、文件、网址或自定义指令后按 `Tab`，选择“固定到顶部”。再次打开动作菜单即可取消固定。

收藏只影响匹配结果的排序，不会创建新的快捷方式，也不会改变原文件。收藏数据保存在 `%APPDATA%\QuickSpark\pinned.txt`。

## AI 问答

QuickSpark 的 AI 功能支持 OpenAI 兼容的 Chat Completions 接口、SSE 流式输出和普通 JSON 回退。它不会在输入过程中自动联网，只有选中提问结果并按 `Enter` 后才会发送问题。当前定位是轻量单轮问答，不是完整聊天客户端。

### 配置接口

输入：

```text
ai settings
```

设置结果包括：

- 接口地址和模型：按 `Enter` 打开 `%APPDATA%\QuickSpark\ai-settings.txt`。
- API Key：按 `Enter` 打开 Windows 安全凭据窗口。
- 配置完成：进入 AI 提问模式。

`ai-settings.txt` 示例：

```text
api_url=https://api.example.com/v1/chat/completions
model=example-model
system_prompt=你是一个简洁、可靠的中文助手。
max_tokens=8192
timeout_seconds=60
thinking_mode=auto
reasoning_effort=high
```

`api_url` 必须填写完整的 Chat Completions 地址，而不是只填写网站域名。支持的配置项：

| 配置 | 说明 |
| --- | --- |
| `api_url` | 完整接口地址；远程服务必须使用 `https://`，`http://` 仅允许 `localhost`、`127.0.0.1`、`::1` 等本机回环地址 |
| `model` | 接口接受的模型名称 |
| `system_prompt` | 可选系统提示词；留空则不发送系统消息 |
| `max_tokens` | 最大输出 token 数，允许 1～65536，新配置默认 8192；长思考建议至少 8192 |
| `timeout_seconds` | 请求超时，允许 5～300 秒，默认 60 秒 |
| `thinking_mode` | DeepSeek V4 思考模式：`auto`、`enabled` 或 `disabled` |
| `reasoning_effort` | 显式开启思考时的强度：`high` 或 `max`；仅在 `thinking_mode=enabled` 时发送 |

API Key 不应写进配置文件。输入 `ai key`，将 Key 填入 Windows 凭据窗口的密码栏；QuickSpark 会把它保存为 Windows 凭据管理器中的通用凭据 `QuickSpark/AI/APIKey`。留空并确认可以清除旧 Key。本地 Ollama、LM Studio 等无需鉴权的兼容接口可以不设置 Key。

接口地址有以下安全限制：

- 远程主机必须使用 `https://`，QuickSpark 不允许把 API Key、系统提示词或问题通过远程明文 HTTP 发送。
- `http://` 只允许 `localhost`、`127.0.0.1`、`::1` 等本机回环地址，供 Ollama、LM Studio 等本地服务使用。
- HTTPS 使用 Windows/WinHTTP 的正常证书校验，不会关闭证书验证。
- 请求采用 WinHTTP 自动代理模式；QuickSpark 不保存代理账号，也不实现自动重试，失败后由用户明确选择重试或重新生成。

旧配置文件缺少 `thinking_mode` 或 `reasoning_effort` 时，QuickSpark 会在启动时补入默认值，并保留已有的接口、模型、提示词、输出长度和超时设置。

### 提问和查看回答

```text
ai Rust 的所有权是什么？
```

操作流程：

1. 输入 `ai 问题`。
2. 结果中会显示将要使用的模型，按 `Enter` 才正式发送。
3. 回答窗口立即弹出；模型返回的思考内容和最终回答会分别接收，不必等待整个响应结束。
4. 思考区默认折叠，只显示状态、字数和耗时；可以点击“展开思考”或“复制思考”。
5. 点击“停止生成”、按 `Esc` 或关闭窗口都会中止当前网络请求；发送新问题也会使旧请求失效。
6. 回答区支持滚动、`Ctrl+A` 全选和 `Ctrl+C` 复制，也可以直接点击“复制回答”。
7. 在主搜索结果中按 `Ctrl+C` 可复制完整回答，按 `Enter` 可再次打开最近一次回答；按 `Tab` 可看到复制和重新生成动作。
8. 关闭已经生成完成的回答窗口只关闭界面，不删除内存缓存；关闭仍在生成的窗口会取消当前请求。
9. 已完成结果的动作菜单提供“重新生成”；接口、模型、提示词、输出长度或思考选项变化后，相同问题不会误用旧缓存。

回答窗口使用 Windows 原生 RichEdit 渲染常用 Markdown，包括多级标题、粗体、斜体、删除线、行内代码、代码块、引用、项目列表、任务列表、链接和基础表格。它不依赖 WebView，也不会执行 Markdown 中的 HTML 或脚本。

流式生成时，连续增量会先合并为一次窗口通知，回答再按 40～250 毫秒的自适应间隔刷新为轻量纯文本；思考状态按约 100 毫秒刷新。生成结束后只进行一次完整 Markdown 排版，避免每个片段都重新解析整篇文档，从而减少闪烁、无效窗口消息和长回答卡顿。“复制回答”复制模型返回的完整原始 Markdown；选中文本后按 `Ctrl+C` 则复制当前看到的排版文本。回答区最多排版最近 200,000 字，超过后会显示提示，但“复制回答”仍复制内存中的完整内容。

### AI 翻译快捷方式

翻译功能直接复用 AI 问答的接口地址、模型、API Key、超时和思考模式，不需要单独配置。输入原文并按 `Enter` 后，同样会立即打开流式回答窗口：

```text
tr 你好，世界                 自动翻译为英语
tr QuickSpark is lightweight  自动翻译为简体中文
tr 日本語の文章です           自动识别日语并翻译为简体中文
tr --to en 早上好             指定翻译为英语
tr --to zh Good morning       指定翻译为简体中文
tr --to ja Good morning       指定翻译为日语
tr --to ko Good morning       指定翻译为韩语
```

可用前缀为 `tr`、`translate`、`fy` 和 `翻译`。未指定目标语言时，由当前 AI 模型识别原文的主要语言：简体或繁体中文翻译为英语，任何非中文语言（例如英语、日语、韩语、法语）翻译为简体中文。混合语言文本按主要语言判断；需要固定方向时可以显式指定目标语言。

指定目标语言必须使用明确标记 `--to`（也支持紧凑写法，例如 `tr ->ja Good morning`），避免把以 `en`、`English` 等词开头的普通原文误认为语言参数。旧写法 `tr en 早上好` 现在会把 `en 早上好` 整体视为待翻译内容；需要固定英语方向时应写成 `tr --to en 早上好`。目标语言支持代码 `en`、`zh`、`ja`、`ko`，也支持 `英语`、`中文`、`日语`、`韩语` 等名称。

翻译请求使用独立的专业翻译系统提示，不会与常规问答的 `system_prompt` 冲突。提示词要求模型只输出译文，在准确传达原意的前提下按目标语言母语者的表达习惯调整语序、句式、词汇和惯用说法，避免逐字直译，同时保持语气、正式程度、情感、信息和排版，并准确处理专有名词与专业术语。待翻译内容中的指令只被视为原文，不应由模型执行；最终效果仍取决于所配置模型的能力。

### DeepSeek V4 思考模式

`thinking_mode=auto` 时不会发送厂商专用参数，由模型和接口决定是否思考；`enabled` 会发送 `thinking.type=enabled` 和所选 `reasoning_effort`，`disabled` 会发送 `thinking.type=disabled`。这些扩展参数面向 DeepSeek V4；使用其他兼容接口时建议保留 `auto`，以免服务端拒绝未知字段。

DeepSeek V4 流式返回的 `reasoning_content` 与最终 `content` 会分开处理：思考时窗口只显示字数和状态，默认不展开；开始输出最终回答后状态切换为“正在回答”。展开思考区时最多渲染最近 10,000 字，以避免超长内容拖慢 RichEdit；“复制思考”始终复制内存中的完整思考内容。

思考可能占用较多输出 token 和响应时间。需要长思考时，建议把 `max_tokens` 设为至少 `8192`，并根据接口速度把 `timeout_seconds` 提高到 `120`～`300`。接口返回 `finish_reason=length` 时，回答窗口会明确提示“达到长度上限，回答可能不完整”；可继续提高 `max_tokens`，但接口自身的模型上限仍然优先。

### 问答缓存与本地保存

- 问题或待翻译文本、最终回答和完整思考内容只保存在当前 QuickSpark 进程的内存中，不写入文件，也不形成问答历史。
- 关闭已经完成的回答窗口不会立刻清空内容；从主搜索结果可以重新打开或复制最近一次回答。
- 开始新问题会替换上一条已完成内容；取消生成会清除可重新打开的问答状态。取消前已收到的部分文字仍可暂时留在当前回答窗口中，关闭该窗口后不再保留。
- 缓存匹配不仅比较问题文本，还比较任务类型、接口地址、模型、系统提示词、`max_tokens`、思考模式和思考强度；改变这些行为相关配置后不会显示旧回答。
- API Key 与超时时间不参与回答内容缓存键；如果只是切换凭据但希望重新请求，请从动作菜单选择“重新生成”。
- 点击“复制回答”或“复制思考”后，内容会进入 Windows 剪贴板，并遵循系统及剪贴板管理软件自身的保存策略。
- 云端接口是否记录问题和回答由接口提供方决定；隐私敏感内容不应发送到不可信的服务。

当前边界：

- 核心请求采用 OpenAI 兼容 Chat Completions 协议；API Key 鉴权使用 `Authorization: Bearer`。DeepSeek V4 思考开关是目前唯一显式支持的厂商扩展字段。
- 仅做文本单轮问答，不保存或自动发送聊天历史；暂不支持图片、附件、工具调用或多轮上下文管理。
- 优先解析 OpenAI 风格的 SSE 数据；若兼容接口忽略流式参数并返回普通 JSON，会在响应完成后自动回退为一次性显示。
- Markdown 采用轻量原生渲染，不执行回答中的 HTML、JavaScript 或其他嵌入内容。
- 响应体有 4 MB 安全上限，底层按最多 64 KB 的网络块读取，避免服务端声明超大可用数据时触发单次巨量分配。
- 取消会关闭当前 WinHTTP 请求；请求代次校验也会阻止迟到的数据写入新窗口。

## 内置计算器

输入 `=` 和数学表达式后会直接显示结果。按 `Enter` 或 `Ctrl + C` 将结果复制到剪贴板；计算在 QuickSpark 进程内完成，不会启动 Windows 计算器。

```text
= 12 * (8 + 3)       -> 132
= -5 + 2.5           -> -2.5
= 17 % 5             -> 2
```

支持 `+`、`-`、`*`、`/`、`%`、括号、小数和一元正负号。除数为零、表达式不完整或包含不支持的内容时会显示格式错误提示，不会提供可复制的计算结果。

## 单位换算

格式为 `%% 数值 源单位 to 目标单位`，也可以用 `in` 代替 `to`：

```text
%% 10 km to mi
%% 100 f to c
%% 1 gib to mb
```

支持的常用单位：

| 类型 | 单位 |
| --- | --- |
| 长度 | `mm`、`cm`、`m`、`km`、`in`、`ft`、`yd`、`mi` |
| 重量 | `mg`、`g`、`kg`、`oz`、`lb` |
| 时间 | `ms`、`s`、`min`、`h`、`day` |
| 速度 | `m/s`、`km/h`、`mph`、`knot` |
| 十进制容量 | `byte`、`kb`、`mb`、`gb` |
| 二进制容量 | `kib`、`mib`、`gib` |
| 温度 | `c`、`f`、`k` |

不同类型之间不能换算，例如重量不能转换为长度。结果按 `Enter` 或 `Ctrl + C` 复制。

## 日期计算

```text
date                         显示今天的日期
date today                   显示今天的日期
date 2026-07-22              显示指定日期
date 2026-07-22 + 30d        向后 30 天
date today - 2w              向前两周
```

日期必须使用 `YYYY-MM-DD` 格式。偏移单位支持天 `d` 和周 `w`；运算符与偏移量之间需要空格。

## 进制转换

```text
hex 255               -> 0xFF
bin 10                -> 0b1010
oct 8                 -> 0o10
dec FF                -> 255
dec 0b1010            -> 10
```

`hex`、`bin` 和 `oct` 默认把未带前缀的输入视为十进制；`dec` 默认把未带前缀的输入视为十六进制。输入也可以显式使用 `0x`、`0b` 或 `0o` 前缀，并支持负整数。

## 窗口切换

```text
win                   列出当前可切换窗口
win chrome            按标题搜索窗口
window obsidian       使用完整前缀搜索
```

QuickSpark 只在输入 `win` 或 `window` 前缀时枚举窗口，不会常驻扫描。隐藏窗口、无标题窗口、工具窗口和已被系统隐藏的窗口不会显示。

## 文件搜索

```text
f 报告                搜索文件或文件夹
file QuickSpark       使用完整前缀搜索
f *.pdf               使用 Everything 通配符
f ext:rs              使用 Everything 扩展名语法
```

文件搜索通过 Everything 的 Unicode Query2 原生 IPC 接口查询：

- 不遍历磁盘。
- 不在 QuickSpark 中维护文件索引。
- 不为每次查询启动 Everything 子进程。
- 至少输入 2 个搜索字符后才发起查询。
- 查询在后台线程中执行，并带有 150 毫秒防抖。
- 每次最多向 Everything 请求 20 条结果，再按设置中心的结果上限显示。

按 `Enter` 打开文件或文件夹，按 `Tab` 可以打开所在位置、复制完整路径或固定到顶部。搜索范围和语法取决于 Everything 自身的索引与设置。

如果显示“Everything 不可用”，请确认 Everything 1.4.1 或更高版本已经启动。QuickSpark 不会自动安装或启动 Everything。

## 搜索排序与个性化

- 固定结果会被提升到匹配结果顶部。
- 应用使用次数和最近使用时间记录在本地，仅用于同一相关性层级内排序。
- 使用统计、常规设置、主题和收藏都通过临时文件原子替换写入；保存失败会提示，收藏失败还会自动撤销本次更改。
- 应用索引刷新失败时会保留旧索引，可以从托盘菜单再次刷新。
- 内置规则会过滤卸载程序、开发工具、管理工具和部分帮助文档等噪声入口。

如需调整应用过滤规则：

- `%APPDATA%\QuickSpark\blocked.txt`：每行填写一个名称或关键词，隐藏匹配的应用。
- `%APPDATA%\QuickSpark\allowed.txt`：每行填写一个名称或关键词，强制恢复被内置规则或屏蔽规则过滤的应用；白名单优先级最高。
- 修改后从托盘菜单选择“刷新索引”，或重启 QuickSpark。

## 资源占用与后台行为

QuickSpark 不会在后台重复建立文件索引，空闲时也不会轮询窗口、文件或 AI 接口。主要后台行为如下：

- 启动或手动刷新时，应用索引在线程中扫描开始菜单和桌面；UWP/系统应用通过系统 PowerShell 的 `Get-StartApps` 获取，进程使用系统绝对路径并有 5 秒超时，不阻塞主窗口。
- 文件搜索维护一个轻量工作线程，只在输入 `f` / `file` 且关键词达到 2 个字符后查询；请求有 150 毫秒防抖，Everything IPC 回复等待上限为 2 秒。
- Everything 的磁盘索引、文件监控和主要内存占用属于 Everything 进程；QuickSpark 每次只请求最多 20 条路径。
- 窗口切换只在使用 `win` / `window` 时调用一次 `EnumWindows`，不会常驻监控窗口标题。
- AI 只在用户按 `Enter` 确认后创建请求线程和 WinHTTP 连接；完成或失败后不保持连接，也没有周期性联网任务。取消会立即停止显示新内容；若系统调用正在阻塞，工作线程会在响应到达或配置超时后安全关闭连接。并发中的新旧请求最多两个。
- 当前仅缓存一条 AI 请求状态。网络响应总量限制为 4 MB；思考和回答的完整文本保留在内存中，但 RichEdit 排版分别限制为最近 10,000 字和 200,000 字。
- 结果集合最多保留 8、12 或 20 条，窗口同时绘制 8 行；滚动不会创建额外结果窗口。

因此，常驻内存主要来自原生窗口、应用索引、搜索键和最近一次 AI 内容。实际数值会随已安装应用数量、字体资源和是否刚完成 AI 请求而变化，不应把单次任务管理器快照视为固定承诺。

## 托盘与生命周期

- 双击托盘图标：显示启动器。
- 右键托盘图标：显示启动器、打开说明、打开设置、刷新应用索引、切换主题或退出。
- 托盘提示会显示当前全局热键；Explorer 重启后会自动重新注册托盘图标。
- 关闭搜索窗口或失去焦点：隐藏，不退出。
- 再次运行 EXE：唤出已经运行的实例，不会创建第二个常驻进程。
- 窗口会显示在鼠标所在显示器，并根据该显示器 DPI 缩放。

- `commands.txt` 和 `ai-settings.txt` 每次使用时都会重新读取，保存后通常无需重启。

- 如需完全重置，先从托盘退出 QuickSpark，再删除 `%APPDATA%\QuickSpark`；这不会自动删除凭据管理器中的 `QuickSpark/AI/APIKey`。

## 隐私策略

- QuickSpark 不包含遥测、账号或云端同步。
- 网页搜索只负责生成 URL 并交给默认浏览器。
- Everything 文件搜索复用外部索引，不重复占用内存建立索引。
- 窗口列表仅在使用窗口切换前缀时枚举。
- 自定义指令配置仅在使用 `;` 时读取。
- AI 仅在用户确认问答或翻译时连接所配置的接口；问题、待翻译文本、翻译指令和系统提示词会发送到该接口。
- AI API Key 从 Windows 凭据管理器按需读取，不会写入 `settings.txt` 或 `ai-settings.txt`。
- AI 请求在独立线程中执行，空闲时不保持网络连接。取消生成采用代次失效和工作线程自清理，避免从 UI 线程关闭仍在使用的同步 WinHTTP 句柄；已发出的请求可能持续到下一次网络返回或配置超时，但其迟到内容会被丢弃。
- AI 问题、回答和思考内容不落盘，只在内存中保留最近一次；展开超长思考时仅渲染末尾 10,000 字，超长回答仅排版末尾 200,000 字，完整内容仍可复制。
- QuickSpark 不会把 AI 问答保存为历史，但接口提供方和 Windows 剪贴板管理器可能有各自的记录策略。
- 应用索引在启动或手动刷新时通过后台线程构建。
- 当前刻意不实现插件加载、搜索历史和问答历史，以保持结构简单、资源可控。

## 安全与可靠性边界

- 远程 AI 端点必须使用 HTTPS；只有本机回环地址允许 HTTP。API Key 只从 Windows 凭据管理器读取，并仅在发起 AI 请求时加入 Bearer 请求头。
- AI HTTP 请求禁用 WinHTTP 自动重定向；接口返回 `3xx` 时会直接报错，Bearer Key、系统提示词和问题不会被自动转发到重定向目标。
- AI 响应有总量和单次读取上限；取消、新请求代次和窗口关闭都有状态校验，迟到的流式片段不会写入后续回答窗口。
- AI 窗口销毁时会先解除窗口状态指针，再释放字体、画刷和缓存；主窗口也会接收独立的“窗口已关闭”通知，避免保留可被 Windows 复用的旧句柄。
- 常规设置、主题、收藏、使用统计以及首次生成的 `commands.txt` / `ai-settings.txt` 模板采用“临时文件 + 原子替换”；保存失败会反馈给用户，而不是静默假装成功。
- 开机启动直接使用 Windows 注册表 API，不调用同名命令行程序；启动时只有注册表中的路径与当前 EXE 完全一致，设置中心才显示为已启用。
- PowerShell、Explorer 和关机程序使用 Windows 目录中的绝对路径，减少当前目录或 `PATH` 中同名程序被意外执行的风险。
- 睡眠、注销、关机和重启必须二次确认；确认框默认选择取消。锁定电脑和打开系统页面不需要确认。
- 显式功能前缀具有独占语义。无效的 `=`、`%%`、`date` 或网页搜索输入会显示格式提示，不会意外回退为应用搜索结果。
- `commands.txt` 是受用户信任的本地配置，不是安全沙箱。目标会交给 Windows Shell 打开；不要导入或运行来源不明的指令配置、脚本或可执行文件。
- QuickSpark 只能保护本地存储和自身请求边界，无法控制 AI 服务商、网页搜索引擎、Everything、Windows 剪贴板历史或第三方剪贴板管理器如何保存数据。

## 常见问题

### 全局快捷键没有反应

快捷键可能已被 PowerToys、Flow Launcher、输入法或其他启动器占用。启动时 QuickSpark 会自动尝试其他内置组合并提示当前选择；如果四组组合都不可用，程序仍会在托盘运行。请从托盘进入设置中心重试，或关闭冲突快捷键。

### 输入 `f` 后提示 Everything 不可用

确认 Everything 1.4.1 或更高版本正在运行，并能正常完成本机搜索。QuickSpark 使用 Everything 原生 IPC，不使用 Windows Search。

### 某个应用搜不到

先从托盘刷新索引。如果仍未出现，检查应用是否存在于开始菜单、桌面或 Windows 应用列表。若被内置过滤规则隐藏，可以将应用名称或关键词写入 `allowed.txt`，然后刷新索引。

### 自定义指令修改后没有生效

确认每行包含两个 `|` 分隔符，别名不含空格或分号，并且该行没有以 `#` 开头。保存后重新输入 `;` 即可，无需重启。

### AI 提示尚未配置

输入 `ai settings`，确认 `api_url` 是完整 Chat Completions 地址，并且 `model` 与接口实际支持的模型名一致。保存配置文件后无需重启。

### AI 提示远程 HTTP 不安全

远程接口必须使用 `https://`。只有 `localhost`、`127.0.0.1`、`::1` 等本机回环服务允许 `http://`；这是为了避免 API Key、系统提示词和问题被明文传输。若服务商只提供远程 HTTP，不建议绕过限制，应在服务端配置 HTTPS 或通过可信的本机反向代理接入。

### AI 返回 401、403 或模型不存在

401/403 通常表示 API Key 无效、权限不足或接口不使用 Bearer 鉴权；重新输入 `ai key` 检查。模型不存在通常表示 `model` 名称与服务端不一致。QuickSpark 会显示接口返回的错误消息，并允许按 `Enter` 重试。

### 相同问题为什么直接显示上次回答

QuickSpark 会在当前进程内复用最近一次相同请求，以避免误按键后重复计费。按 `Tab` 打开动作菜单并选择“重新生成”即可再次请求。改变接口、模型、系统提示词、`max_tokens` 或思考设置也会自动使旧缓存失效。

### `tr en 文本` 为什么没有指定英语

为避免把正常原文开头的 `en` 或 `English` 误判成参数，指定目标语言必须写成 `tr --to en 文本`，或使用紧凑形式 `tr ->en 文本`。没有 `--to` / `->` 标记时，后面的全部内容都会交给模型自动识别语言。

### DeepSeek 没有显示思考过程

先在 `ai-settings.txt` 中把 `thinking_mode` 改为 `enabled`，并确认使用的模型和接口支持 DeepSeek V4 思考参数。如果设置为 `auto`，QuickSpark 不发送思考开关，是否返回 `reasoning_content` 完全由服务端决定。其他 OpenAI 兼容接口不一定支持这些字段，建议保持 `auto`。

### 思考很长，窗口会越来越卡吗

思考默认折叠，只更新字数和耗时。手动展开后也只渲染最近 10,000 字，因此长思考不会把全部文本持续排版到窗口中；“复制思考”仍会复制内存中的完整内容。长思考更容易触发输出长度或超时限制，可提高 `max_tokens` 和 `timeout_seconds`。

### 回答显示“达到长度上限”

接口返回了 `finish_reason=length`，说明回答可能不完整。可在 `ai-settings.txt` 中提高 `max_tokens` 后选择“重新生成”；如果仍被截断，通常是模型或服务端还有更低的输出上限。`finish_reason=content_filter` 则会显示内容过滤结束，不能靠提高长度解决。

### 流式回答时文字偶尔重新排版

QuickSpark 在流式阶段使用轻量纯文本批量刷新，不再反复解析未闭合的 Markdown；生成结束后才统一渲染最终格式。因此过程中可能暂时看到 Markdown 标记，但结束后会稳定为排版文本，闪烁也会明显减少。

### 关闭回答窗口后，问答会保存吗

不会保存到磁盘。已完成的最近一次回答会暂存在进程内存中，所以关闭窗口后仍可从主搜索结果重新打开；开始新问题会替换它，退出 QuickSpark 会清空。取消生成后，已收到的部分文字可以暂时留在当前回答窗口中，但不会作为完整回答供主搜索结果重新打开。复制到剪贴板的内容不受 QuickSpark 控制。

### 无法覆盖或替换 EXE

正在运行的 EXE 会被 Windows 锁定。请先从托盘彻底退出 QuickSpark，再复制新版本或执行 `cargo build --release`。

### 设置已应用但提示无法保存

检查 `%APPDATA%\QuickSpark` 是否可写、磁盘是否已满，以及安全软件是否拦截临时文件替换。主题或普通设置可能在当前进程中暂时生效，但下次启动会恢复旧值；收藏保存失败时 QuickSpark 会立即撤销本次固定或取消固定。

### Explorer 重启后托盘图标消失

QuickSpark 会监听 Windows 的 `TaskbarCreated` 消息并自动重新添加托盘图标。若仍未恢复，可以再次运行同一个 EXE：单实例逻辑会唤出已经运行的 QuickSpark；也可以在任务管理器确认进程是否仍存在。

### 移动 EXE 后开机启动失效

开机启动记录的是启用时的 EXE 完整路径。移动文件后，在设置中心先关闭再重新开启“开机自动启动”。

## 开发架构

搜索功能通过统一的 Provider 注册表组织。每个 Provider 接收 `Query` 和只读上下文，返回带分数及动作列表的 `ResultItem`。窗口层只负责显示统一结果、处理输入并执行 `Action`。

```text
用户输入
   |
   v
ProviderRegistry
   |-- Applications
   |-- Help
   |-- Settings
   |-- Commands
   |-- System
   |-- FileSearch
   |-- WebSearch
   |-- AI
   |-- Calculator
   |-- Converter
   `-- WindowSwitcher
   |
   v
合并 / 独占模式 / 排序 / 截断
   |
   v
ResultItem -> Action -> Windows Shell / Clipboard / Provider 状态
```

带明确前缀的功能通常返回“独占结果”，避免与普通应用搜索混在一起。普通结果统一应用收藏提升、分数排序和数量截断。

耗时工作不会直接占用 Win32 主消息循环：

```text
主 UI 线程
   |-- 应用索引线程 -------- INDEX_READY -------> 刷新 Provider
   |-- Everything 工作线程 - FILE_SEARCH_READY -> 刷新文件结果
   `-- AI 请求线程 ---------- AI_READY ---------> 合并增量 / 更新回答窗口

回答窗口 -- AI_CANCEL / AI_WINDOW_CLOSED ------> 主窗口清理请求与窗口状态
```

后台结果都带有请求代次或窗口身份校验。旧 Everything 查询、已取消 AI 请求以及已经销毁窗口的迟到消息会被丢弃；AI 增量进入线程安全队列后只安排一个待处理窗口通知，主线程一次性排空，避免高频 token 造成消息风暴。

Win32 窗口状态通过窗口用户数据保存，并使用 `RefCell<App>` 的受检短借用访问，不伪造 `'static mut` 生命周期；同步 Win32 调用前会先提取拥有型数据或可复制句柄，重入借用冲突会安全返回。窗口销毁时先把用户数据指针清零；若检测到同步重入产生的活跃借用，则保留状态到进程退出，否则立即释放 `App` 及其字体、画刷和 AI 状态。回答窗口资源、网络句柄和托盘图标也有明确的创建与清理位置。

主要模块：

- `src/model.rs`：查询、结果、统一动作、AI 请求类型、设置动作和使用统计模型。
- `src/providers/`：所有内置搜索与工具 Provider；其中 `ai.rs` 负责问答/翻译状态与流式事件，`ai/transport.rs` 隔离 WinHTTP、SSE/JSON 和 URL 解析。
- `src/search/`：拼音生成、模糊匹配和排名。
- `src/storage.rs`：常规设置、AI 配置、主题、使用统计、过滤规则、自定义指令、收藏、原子写入和开机启动注册表。
- `src/platform/windows/ai_window.rs`：AI 回答窗口、窗口关闭通知、流式状态和思考区交互；`ai_window/rendering.rs` 负责 RichEdit 与 Markdown 渲染。
- `src/platform/windows/markdown.rs`：原生 RichEdit Markdown 解析与排版。
- `src/platform/windows/ai_credentials.rs`：Windows 凭据管理器中的 API Key 读写。
- `src/platform/windows/shell.rs`：Windows Shell 启动与系统程序路径解析。
- `src/platform/windows/` 的其余模块：日期、剪贴板和窗口相关 Windows 封装。
- `src/main.rs`：Win32 主线程、绘制、键盘鼠标、动作执行、托盘和生命周期。
- `src/tests.rs` 及模块内 `tests.rs`：与生产代码分离的单元和组件测试。
- `build.rs`：Windows 图标资源嵌入。

新增内置功能时，优先实现 `Provider` 并注册到 `ProviderRegistry`，不要把业务解析逻辑直接放进窗口消息处理。未来若加入第三方扩展，优先考虑独立进程和 IPC，而不是在主进程直接加载不受信任的 DLL。

## 开发验证

```powershell
cargo fmt --check
cargo test
cargo test --release
cargo clippy --all-targets -- -D warnings
cargo build --release
```

提交或发布前至少应保证格式检查、完整测试和 Clippy 零警告；`cargo test --release` 还能覆盖与最终优化配置一致的代码路径。Release 构建前若 QuickSpark 正在运行，需要先从托盘退出，因为 Windows 会锁定正在执行的 EXE。

Everything 现场 IPC 测试默认忽略；在 Everything 正常运行时可单独执行：

```powershell
cargo test live_everything_query_reaches_the_running_index -- --ignored
```

Release 配置启用了单代码生成单元、LTO、体积优化和符号剥离，具体设置见 `Cargo.toml`。
